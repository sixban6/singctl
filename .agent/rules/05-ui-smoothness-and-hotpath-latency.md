# 规则 05：WebUI 页面流畅、首屏秒开与热路径零卡顿铁律

任何涉及客户端/服务端 WebUI 前端（`web/src/`）或后端状态/轮询接口（`internal/webui/`、`internal/serverweb/` 及被其调用的领域探针）的新增与修改，**必须将“页面流畅、首屏秒开、绝不卡死”作为硬性质量红线**。

## 1. 后端热路径零阻塞红线（`/api/status` 与高频 GET 接口）

- **响应时延目标**：首屏与高频轮询接口（如 `GET /api/status`、`GET /api/system/*`）在局域网常规场景下必须保持 **`<= 200ms`**，严禁在热路径中引入无条件秒级同步阻塞。
- **外部 CLI 调用前必做廉价快路径判定**：调用可能内部重试超时的外部 CLI 前，必须先通过内存态、`/proc` 进程检查或 Unix Socket `os.Stat` 确认目标服务在运行。例如 `tailscaled` 未运行时必须 `0ms` 直接返回 `running=false`，**严禁**盲目执行 `tailscale status --json` 触发 2 秒空等重试。
- **二进制版本号按文件指纹缓存**：`sing-box version`、`tailscale version`、`AdGuardHome --version` 等静态元数据必须按 `path + mtime + size` 做并发安全内存缓存，禁止在每次状态轮询热路径反复 `fork/exec` 拉起重型子进程。
- **聚合状态接口强制单飞短缓存**：多路并发探测聚合接口（如 `/api/status`）必须通过 `internal/common/swrcache.Bounded` 做短 TTL（如 3 秒）单飞合并与有界超时陈旧值回退，并在写操作（`POST`/`PUT`/`DELETE`、`saveConfig`）后自动失效缓存，避免多标签页或高频轮询拖慢路由器 CPU 与首屏响应。

## 2. 前端首屏秒开与防假死红线（`web/src/`）

- **同源会话级首屏快照回显**：核心状态（如 `client:status`）需在当前站点 `sessionStorage` 保留轻量快照（退出登录或 `401` 时立即清除），刷新或重开页面时 **0ms 先行渲染界面，同时后台静默刷新最新数据**，避免每次打开都白屏干等接口返回。
- **严禁吞掉首屏请求错误**：调用 `useCachedQuery` 等数据 Hook 时禁止丢弃 `error` 状态。首屏尚无缓存数据时：
  - 加载中必须展示结构化骨架屏（而非光秃秃的一行“正在连接…”）；
  - 一旦请求失败或超时，必须立即展示明确错误原因与 **「立即重试」按钮**，彻底杜绝静默卡死假象。
- **保持低负载流畅交互**：非当前页签按需懒加载，避免后台不可见页签持续发请求；状态轮询仅局部更新变化区域，避免在手机或低算力设备上造成掉帧与卡顿。
